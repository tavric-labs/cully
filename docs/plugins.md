# Install as a plugin

`cully setup` is the supported install. It also writes hooks, the skill and the MCP connection into each agent's user configuration. The repository additionally ships one plugin per agent, so you can add Cully's hooks and skill from the agent's plugin marketplace and let the agent update them.

Use **one** route per agent. A plugin and `cully setup` both register the same hooks, so running both makes each hook fire twice.

## What a plugin contains

| Agent | Hooks | Skill | `/cully` command |
| --- | --- | --- | --- |
| Claude Code | Stop, SessionStart, SessionEnd and an asynchronous tool-event hook | Yes | Yes |
| Cursor | Session, response, stop and tool-event hooks | Yes | Yes |
| Codex | SessionStart and an asynchronous tool-event hook | Yes | No: use `/prompts:cully` from `cully setup` |

The hooks are the same ones setup installs. A test installs setup into a scratch home and fails if a plugin's hooks differ, and another test fails if a committed plugin file differs from its generator.

A plugin does not do three things, so keep these steps:

- **Install the CLI.** Hooks run `cully` from your `PATH`, where setup writes an absolute path. Run the [installer](/installation) first.
- **Connect memory.** A plugin cannot know your server URL. Run `cully mcp add --agent AGENT --url URL`, adding `--oauth` for a sign-in server.
- **Claude Code's status line.** Plugins cannot set it. Run `cully setup --agent claude` if you want the status line.

## Claude Code

```text
/plugin marketplace add tavric-labs/cully
/plugin install cully@cully
```

Restart Claude Code, then run `cully run claude` for the terminal panel. Claude Code validates this plugin and marketplace in CI with `claude plugin validate`.

## Codex

```sh
codex plugin marketplace add tavric-labs/cully
```

Then install **Cully** from the Plugins directory in the Codex desktop app and start a new session. Codex runs plugin hooks only after you review and trust them, and OpenAI documents plugin hooks as supported for plugins you install yourself, not for its public directory. The manifest follows OpenAI's plugin documentation. It has not been installed in a live Codex here.

## Cursor

The repository has a Cursor plugin and a marketplace manifest at `.cursor-plugin/marketplace.json`, in the format Cursor's plugin reference describes. That reference does not cover installing from a repository, and the plugin has not been installed in a live Cursor here. `cully setup --agent cursor` is the verified route.

## Develop the plugins

The files under `plugins/` and the three marketplace manifests are generated by `PluginFiles` in `internal/cully/plugins.go`. After changing a hook, the skill or the `/cully` command, regenerate them:

```sh
CULLY_UPDATE_PLUGINS=1 go test ./internal/cully -run PluginFiles
```

The manifests carry no version, so each agent tracks the repository instead of pinning an old release.
