# Cully UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cully ui` serves a browser UI where you give a task, Cully gathers context and scouts, spawns a Claude agent on the next OAuth token in its own git worktree, and you keep talking to that agent; the same page also shows Cully's existing status, timeline, replay, handoff, suggestions, impact and jobs.

**Architecture:** One in-process engine (`uiManager`) owns agents, tokens and the context pipeline. A small HTTP server (embedded static files, JSON API, SSE) is the first client. A terminal UI (`cully agents`, phase 2, separate plan) will be a second client of the same API. Existing Cully commands render the dashboard panels by writing to a buffer; nothing is reimplemented.

**Tech Stack:** Go 1.26 stdlib only (`net/http`, `embed`, `os/exec`), vanilla JS/CSS, `claude` CLI stream-JSON mode.

**Spec:** the design agreed in conversation (option 1: structured headless agents; browser agents window plus full Cully dashboard; terminal UI as a later client). No separate design doc; the user opted out of the question round.

## Global Constraints

- One Go module `github.com/mcp-runtime/cully`; code in `internal/cully`, entry in `cmd/cully/main.go`. No new dependencies.
- Token values are never printed, logged, returned by the API or stored in events; the API exposes only a 1-based token index and a count. Event text is redacted of any token value.
- Default bind `127.0.0.1:7777`. Every `/api/*` call requires the UI token (cookie `cully_ui` or `Authorization: Bearer`); mutating calls also require header `X-Cully-UI: 1`; loopback binds reject a non-loopback `Host`. UI token file `ConfigDir()/ui-token`, mode 0600, 32 random bytes hex, compared in constant time.
- Browser JS renders agent text with `textContent` only; CSP `default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data:`.
- Agents only run in a git worktree `ConfigDir()/ui-worktrees/<id>` on branch `cully/<slug>-<id>`, repo restricted to the `--repo` allow-list. Agents do not push.
- Agent transcripts stay in memory only; the journal receives only the fields `journal.go` allows (class, outcome, relative path, op, command hash).
- Every PR updates `CHANGELOG.md` under `Unreleased`. Run `gofmt`, `go vet`, and `go test -race ./...` before publishing. No commit unless the user asks.

## Review Focus

- Request from another origin or with a forged `Host` (DNS rebinding) must be rejected: tested in Task 5.
- Agent output containing `<script>` or a token value must never reach the page unescaped or unredacted: Tasks 2 and 6.
- `repo` outside the allow-list or `../` traversal must be refused: Task 5.
- `claude` missing or exiting non-zero must end the agent as `failed` with a visible error event, not hang: Task 3.
- Context or scout stage failing/timing out must not block spawning: Task 4.

## Out of scope for this plan
